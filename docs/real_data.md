# Real-data analysis: GBSG2

[examples/gbsg2_analysis.py](../examples/gbsg2_analysis.py) performs a complete
analysis of the German Breast Cancer Study Group 2 dataset bundled with
scikit-survival. The dataset has 686 subjects, eight covariates, and 299 observed
recurrence-free-survival endpoints before the example's follow-up restriction.
See the [dataset documentation and original study references](https://scikit-survival.readthedocs.io/en/stable/api/generated/sksurv.datasets.load_gbsg2.html).
Loading it requires no external data download.

```bash
python examples/gbsg2_analysis.py --output gbsg2-results.json
python examples/gbsg2_analysis.py --quick --output /tmp/gbsg2-smoke.json
```

Both modes use the full cohort. The quick mode reduces cross-validation folds
and fitting budgets, so it is an execution check rather than a final analysis.
The JSON report records the configuration, provenance, every candidate/fold,
warnings, errors, convergence diagnostics, selected model, held-out metrics,
and model-based probability predictions.

## Analysis choices

Times are converted from days to years. A prespecified administrative horizon
of six years is applied to every subject before splitting: follow-up is capped
at six and events after that point become censored. No subjects are dropped.
This truncates follow-up for 36 subjects and removes three later observed
events in the bundled dataset. It provides common follow-up support for
training/test censoring calculations; it does not infer that those subjects
were cured. The chosen horizon is part of the analysis specification.

An event-stratified 75/25 split with seed 73 reserves 172 subjects for final
evaluation and 514 for training. Model selection uses only the training cohort:

1. Numeric features are median-imputed and standardized; categorical features
   are imputed and one-hot encoded with a reference category.
2. Each cross-validation fold fits its own preprocessing and cure estimator.
3. MixtureCure and PromotionTimeCure are compared by mean validation concordance.
   Candidate errors and nonconvergence remain visible in the report.
4. The eligible selected model is refitted on the full training cohort.
5. The held-out cohort is evaluated once after selection, using training
   outcomes to estimate censoring weights.

This selects a model family; it is not an exhaustive hyperparameter search.
The test cohort is never used to choose the model or fit preprocessing.
Review fit eligibility and convergence diagnostics before interpreting results.

## What to interpret

The held-out report contains IPCW concordance, time-dependent AUC, and integrated
Brier score over the stated one-to-five-year interval. Concordance and AUC
measure discrimination; the Brier score measures probability error. See the
[scikit-survival evaluation guide](https://scikit-survival.readthedocs.io/en/stable/user_guide/evaluating-survival-models.html).

Cure probabilities are extrapolations implied by the selected latency and count
model. Actual cure labels are unavailable in this dataset. Good predictions
within five years do not establish that the model's infinite-time cure fraction
is correct. A single split also does not establish superiority of one estimator.
The example supports a reproducible predictive analysis and does not estimate
causal treatment effects.

In the recorded full three-fold development run, both candidates converged in
all folds. MixtureCure was selected by training-fold concordance; its held-out
IPCW concordance was about 0.644, mean AUC 0.691, and integrated Brier score
0.196. These values describe this split, horizon, grid, and software versions;
the report generated by your run is the source of its actual results.
